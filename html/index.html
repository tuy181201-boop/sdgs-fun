SDGS — Полная документация проекта

Автономная платформа для живых, детерминированных игровых миров без облачных серверов и интернета.

Автор: Куралесенко Д. В. Версия: 1.0 Дата: сентябрь 2026 Лицензия: MIT

1. Обзор проекта

SDGS (System Distributed Game Server) — платформа для создания живых, автономных игровых миров без облачных серверов и обязательного интернета. Работает на кластере микроконтроллеров (ESP32, Arduino) и имеет монолитное ядро для Win7+.

Три значения аббревиатуры

🔧 Synchronized Deterministic Game System

Инженерное значение: система синхронизированного детерминированного игрового процесса.

🧬 Self-Discovering Generative Sandbox

Моддерское значение: самопознающая генеративная песочница.

📖 Stories Dreamed Game Spaces

Игровое значение: игровые пространства, рождаемые историями.

Ключевые принципы

  • Автономность — работа без интернета, питание от аккумулятора, связь 4G.
  • Детерминизм — фиксированная физика 60 Гц, 64-битный LCG, Fixed48_20.
  • Открытость — все форматы документированы (ZIP+JSON).
  • Мультиязычность — 22 языка + LLVM IR.
  • Мультиплатформенность — ESP32, Win7+, Android, iOS.

5. Детерминизм и LCG

Для обеспечения воспроизводимости мира на всех платформах используется 64-битный линейный конгруэнтный генератор (LCG).

Параметры LCG

ПараметрЗначение
Модуль m2^64
Множитель a0x9E3779B97F4A7C15
Приращение c0xBF58476D1CE4E5B9
Период2^64 ≈ 1.8 × 10^19

Формула: X_{n+1} = (a * X_n + c) mod 2^64

Применение

  • Генерация мира (WTPS, VXPS) — сид региона = мир_сид + координаты.
  • Поведение NPC — каждое NPC имеет свой LCG от UID.
  • Экономика — колебания цен, спрос.
  • Квесты — выбор целей и наград.
  • Физика — начальные условия для симуляций.
  • Музыка (TrackScript) — генерация вариаций.

Fixed48_20

Все физические вычисления ведутся в формате Fixed48_20 (48 бит целая часть, 20 бит дробная) — для полного детерминизма на всех платформах.

6. Pascal-скрипты

Pascal-скрипты — это голографические базы данных, где код и данные неразделимы. Скрипт описывает алгоритм генерации, а при выполнении создаётся бинарный слепок.

Обязательная структура

Pascal 
program <32-hex-UID>;

uses
  <библиотеки>;

type
  TMyData = record ... end;
  TMyArray = array[...] of ...;

var
  MyArray: TMyArray;

implementation
  // Вспомогательные процедуры

begin
  GenerateData;
  SaveToFile('data.bin');
end.

KRL — поведение NPC

KRL 
entity Wolf {
    state idle {
        on_enter: play_anim("wolf_idle.anim");
        transition: if (player.distance < 10) -> chase;
        transition: if (health < 20) -> flee;
    }
    state chase {
        action: move_to(player.position);
        transition: if (player.distance < 2) -> attack;
    }
    state attack {
        action: attack(player, damage = 5);
        transition: after(1.0) -> chase;
    }
}

7. Бинарный формат ресурсов

Все бинарные файлы (VXL, SWT, ANIM, EFX, FLD) используют единый формат заголовка с переменными длинами и поддержкой любого числа измерений.

Формат 
[UID (16)] [D (1)] [L₁…L_D] [S₁…S_D] [Data]
ПолеРазмерОписание
UID16 байтУникальный 128-битный идентификатор
D1 байтКоличество измерений (до 255)
Li1 байт каждыйДлина i-го размера
SiLi байтРазмер по i-му измерению (big-endian)
Data∏ Si × (байт на элемент)Многомерный массив

Измерения для VXL (с массой)

  • D = 4 (X, Y, Z, C)
  • C = 5 (R, G, B, A, Mass — uint64, микрограммы)
  • Размер вокселя: 12 байт (4 + 8)

Подпрограмма сохранения (Pascal)

Pascal 
procedure SaveVXL(const Filename: string; const Model: TVXLModel);
var
    F: file;
    Header: array[0..28] of byte;
begin
    FillChar(Header, SizeOf(Header), 0);
    Move(Model.UID, Header[0], 16);
    Header[16] := 4;         // D = 4
    Header[17] := 1;         // Lx
    Header[18] := 1;         // Ly
    Header[19] := 1;         // Lz
    Header[20] := 1;         // Lc
    Header[21] := Model.Width;
    Header[22] := Model.Height;
    Header[23] := Model.Depth;
    Header[24] := 5;         // C = 5
    Assign(F, Filename);
    Rewrite(F, 1);
    BlockWrite(F, Header, SizeOf(Header));
    // ... запись вокселей
    Close(F);
end;
⚠️ Теоретический максимум При D = 255 и L = 255 заголовок занимает 65 297 байт, а объём данных может достигать 10^156600 байт — число, превышающее количество атомов во Вселенной (10^80).

8. TrackScript (музыка)

TrackScript — это DSL для описания музыкальных треков. Подробности — в документации формата .ts. Поддерживает ноты, аккорды, эффекты (включая 8D), модуляции.

Пример трека

TrackScript 
track "8D_Demo" {
    sections: "verse";
    tempo: 120;
    rotation_speed: 0.5;
    reverb: 0.3;

    part "verse" {
        node start {
            action: start_voice(voice="lead", phrase="melody");
            duration: 32;
            transition: end;
        }
    }

    voice "lead" {
        phrase melody {
            note(freq=C4, duration=1, volume=0.8, start=0);
            note(freq=E4, duration=1, volume=0.8, start=1);
            note(freq=G4, duration=2, volume=0.8, start=2);
            transition: after(4) -> melody;
        }
    }
}

8D-эффект

  • Вращение панорамы по синусоиде (динамическое панорамирование).
  • Реверберация (задержка с затуханием).
  • Квадро-выход (FL, FR, RL, RR) с задержкой 20 мс для задних каналов.

Макрос нот

Все 120 нот (C0–B9) заданы в файле notes.def, вычислены по формуле 440 × 2^((midi-69)/12).

9. Модуль орбитальной камеры

Камера реализована на C++20 с использованием Fixed48_20 и LCG для детерминированных микроколебаний.

Параметры

  • Сферические координаты (radius, yaw, pitch).
  • Плавность (smoothnessPos, smoothnessRot).
  • Чувствительность (sensitivityYaw, sensitivityPitch).
  • Дыхание (enableBreath, breathAmplitude, breathFrequency).
  • Коллизии (enableCollision, collisionOffset).

Предустановки

ПресетНазначение
DefaultСтандартный режим
CombatБлиже и ниже для боя
DialogueДальше и выше для диалогов
CinematicПлавный, для кат-сцен
VehicleДля транспорта

Параметры камеры хранятся в DNA-файле, что делает её частью генома мира и позволяет AI Core изменять её на лету.

14. Консольная версия (по модели Sony)

По аналогии с PS4 + PSVR Processing Unit, консольная версия SDGS разделена на два устройства.

Устройство 1 — Main Console

  • Чип: STM32MP25 (2× Cortex-A35 @ 1.5 ГГц + GPU + NPU).
  • ОС: Linux.
  • Задачи: рендеринг 3D (1080p60), AI Core (Python + NPU), интерфейс, сеть (Ethernet + TSN).

Устройство 2 — Realtime Unit

  • Чип: STM32H7 / STM32G4 (Cortex-M33/M7).
  • Задачи: барьерная синхронизация 60 Гц, Fixed48_20 физика, LCG 64-bit, CAN-FD, GPIO, Watchdog.

Протокол связи

КаналНазначениеСкорость
SPIОсновной поток данных~5 МБ/с
UARTКоманды, лог~300 КБ/с
GPIOПрерывания (VSYNC, TICK)~1 МГц
💡 Сравнение с Sony PS5 = APU + Tempest Engine (3D-аудио) + PSSR (AI-апскейлинг).
SDGS = Main Console (A35) + Realtime Unit (M33) — аналогичное разделение частот и задач.
