# HTML + CSS + JS

## Почему для документации используется HTML?

В качестве основного формата документации в этом репозитории выбран **HTML** (в связке с CSS и JavaScript), а не Markdown или обычный текст.

### Причины такого выбора

- **Полный контроль над внешним видом.** HTML + CSS позволяют оформить документацию так, как нужно: настроить типографику, цвета, отступы, таблицы и навигацию без ограничений, которые есть у Markdown.
- **Интерактивность.** JavaScript даёт возможность добавить на страницы документации динамические элементы: переключатели, вкладки, поиск по разделам, сворачиваемые блоки и т.д.
- **Работает офлайн без дополнительных инструментов.** Пользователь, скачавший репозиторий как ZIP-архив, может открыть HTML-файл в любом браузере и сразу увидеть готовую страницу — без редакторов кода, конвертеров и установки дополнительного ПО.
- **Единый источник правды.** Вся документация ведётся в HTML-файлах, поэтому не возникает ситуации, когда нужно синхронизировать `.md` и `.html` вручную.

### Как это устроено в репозитории

- Документация хранится в виде HTML-страниц (с подключёнными CSS и JS).
- Для локального просмотра достаточно открыть нужный `.html`-файл в браузере.
- При необходимости HTML-документацию можно опубликовать через **GitHub Pages**, и она будет доступна как обычный сайт.

### Итог

HTML для документации — это осознанный выбор в пользу **гибкости оформления, интерактивности и удобства офлайн-просмотра**. Если в будущем понадобится автоматическая генерация страниц из Markdown, это можно добавить отдельным шагом, не меняя текущий формат.
